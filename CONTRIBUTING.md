# Contributing (贡献指南)

Thank you for considering contributing to the **Theory & Governance (理论号)** line of this account.

We follow a shared governance model documented in `AGENTS.md` (six areas: persona / commands / project structure / code style / git workflow / boundaries) and in the account-level GOVERNANCE/community files.

## Before you contribute

1. Read `AGENTS.md` in the target repository first (commands, structure, style, boundaries).
2. Check open issues / PRs to avoid duplication.
3. For any external-facing release, approval by the account owner (Steven) is required.

## Contribution flow

1. Fork or branch from the default branch (`main`).
2. Make a focused change; keep commit messages descriptive (EN preferred, CN accepted).
3. Add or update tests/evidence where the change affects evaluation gates (reports must keep bilingual + commit SHA + rerun provenance).
4. Open a Pull Request. Template: see `PULL_REQUEST_TEMPLATE.md`.

## Boundary rules (abridged)

- **Always**: cite evidence, keep reports reproducible, mark unpublished work as PROPOSAL.
- **Ask first**: new repositories, external publishing, license changes, key/credential operations.
- **Never**: mix accounts (theory/product/evaluation write isolation), commit secrets, publish without approval, or claim certification we do not hold.
